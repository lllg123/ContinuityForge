# ContinuityForge 现有架构审计（2.0 重构起点）

本报告基于当前 MoonBit 源码、测试、示例、`web/app.js` 与 CI 配置。这里描述的是重构前已实现的行为，不将计划中的通用调度、优化或 Web 集成算作现有能力。

## 已实现能力与模块边界

| 模块 | 当前职责 | 处理建议 |
| --- | --- | --- |
| `model.mbt`、`dependency.mbt` | 服务/组件标识、依赖边校验、稳定的依赖优先拓扑序 | 保留领域 API；通用任务图另建独立包 |
| `impact.mbt` | 沿反向依赖广度优先传播，输出受影响资产和一条稳定路径 | 保留为故障恢复场景能力 |
| `bia.mbt` | 时间单位、影响等级、RTO/RPO 与最大中断时间校验 | 保留在业务连续性适配层，不进入通用核心 |
| `recovery.mbt` | 资源独占、不可抢占的恢复任务排程、下界和目标窗口检查 | 保留兼容 API；后续显式适配通用模型并比较基线 |
| `playbook.mbt`、`drill.mbt` | 步骤前置与审批状态、演练审计时间线 | 保留为领域工作流，不混入调度算法 |
| `storage.mbt`、`auth.mbt` | 内存中的不可变快照和本地角色授权 | 保留；当前不是跨进程持久化或服务端身份系统 |
| `api.mbt` | 对领域构造、图、BIA、影响和恢复操作的门面 | 保留兼容性；通用调度 API 放在独立包 |
| `web/` | 浏览器本地库存、BIA、故障和恢复视图、证据 JSON 导出 | 保留界面；调度与传播计算需在后续阶段接入 MoonBit |

目前根目录 `moon.pkg` 同时编译全部领域模块；`core.mbt` 只提供 JS 集成标记。`examples/minimal` 运行领域闭环，`examples/recovery_window` 运行 MoonBit 排程，`cmd/js_probe` 与 `integration/js/smoke.mjs` 仅检查 JS 编译/执行边界。`web/app.js` 自行实现故障传播、恢复队列和串行时间估计，没有调用 MoonBit 排程；两者的结果不能视作等价。CI 检查多目标格式、检查、测试、构建与两个示例，但没有算法对比实验。

## 算法及复杂度

令 `n` 为资产/任务数，`m` 为依赖边数，`r` 为资源数。以下是当前数组和线性查找实现的上界，不是基于哈希索引的理想复杂度。

- `dependency.mbt` 的 `build_adjacency` 对节点去重是 `O(n²)`；每条边线性查找端点并扫描已有出边，最坏为 `O(nm + m²)`。DFS 环检测和 Kahn 队列拓扑遍历在邻接表建好后为 `O(n+m)`，DFS 深度最坏 `O(n)`。
- `impact.mbt` 复用上述建图与环检测，BFS 本身为 `O(n+m)`；每个新路径复制整条前缀，链式图的路径输出可达 `O(n²)` 空间与复制成本。
- `recovery.mbt` 重新拓扑排序；反向遍历计算下游最高影响等级与最长剩余路径，扫描每个资源的任务负载。每轮对未选任务扫描所有前置边，约为 `O(n²m)`；每次找资源空档反复扫描已有排程，保守最坏 `O(n³)`。建图的线性查找成本同上。排程结果本身为 `O(n)`，图及辅助数组约为 `O(n+m+r)`。

## 恢复排程的真实约束与边界

`prioritize_recovery` 要求正时长、无环依赖、已列出的资源；每个任务使用一个独占资源，不可抢占。可用资源分别并行，同一资源不能重叠。候选任务必须先满足全部前置任务已**排入**计划；选择顺序依次为最高下游影响等级、下游剩余路径、当前影响等级、较短时长和资产键。选中后，开始时间不早于前置任务结束时间，并向后搜索该资源最早的完整空档。因此返回数组是选择顺序，不一定是时间顺序。

两个下界分别是最长依赖路径时长和最大单资源总负载。若其中较大者超过目标窗口，可证明窗口不可行；若下界未超标而当前排程超标，只能证明**这一次启发式排程**未达标。`total_time_minutes` 是所有结束时间的最大值，而非时长总和。`docs/recovery-scheduling.md` 的 70 分钟工作量、45 分钟实际窗口案例可复现这一差别。

这一规则没有搜索替代任务次序、回溯或最优性证明。影响等级优先可能让共享资源上的长关键路径等待，从而产生比最优方案更大的 makespan。当前没有同约束下的拓扑/关键路径基线、精确解参照、独立排程可行性检查或固定预算的优化实验；不能声称全局最优或量化改进率。`TimeSpan::as_minutes` 的通用转换本身没有溢出检查；恢复入口另用 `checked_recovery_minutes` 检查正数分钟范围。

## 测试覆盖与缺口

现有 MoonBit 测试覆盖标识与边校验、缺失/重复/环、传播去重、BIA 边界、资源不可用、目标下界、并行和空档填充、审批状态、审计顺序、内存快照与角色权限。`recovery_test.mbt` 固定了已知排程案例，但没有与精确最优解对比；也缺少通用任务模型、两个场景复用同一调度接口、随机规模性能和 Web/MoonBit 一致性测试。

## 本轮三个提交的迁移边界

1. 本审计只记录当前事实和局限，不改变运行行为；通过审查文档 diff 验收。
2. 新建无企业领域类型依赖的 MoonBit 任务包，定义任务、依赖、资源、时长、优先级、约束及结果数据；用构造校验和测试验收，保留根包 API。
3. 在该包上建立统一问题校验、排程结果校验及算法接口，明确 makespan 目标和资源/前置约束；用恢复与 CI 流水线形状的输入检查复用性。算法基线、优化和业务适配器属于后续独立提交。

本轮不宣称完成 ContinuityForge 2.0 的其余 P0 验收项。
